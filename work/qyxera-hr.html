Slack clock-in and payroll tracker

Staff clock in by typing a word in Slack. Nineteen rounds of fixes against real daily use turned that simple idea into something payroll can be run from.

The problem

Timesheets are filled in on Friday from memory

Any system that asks a busy person to record their hours in a separate tool gets filled in retrospectively, approximately, and in a rush. The numbers that come out the other end are then used to pay people.

The engineering

The decisions that actually mattered

Accept how people actually type

Not buttons, not a workflow form: plain words, fuzzy-matched, so "iin", "In " and "back!" all land correctly. Every character of friction between a person and clocking in is a shift that gets logged wrong later.

Overnight shifts broke the first three versions

A shift starting 22:00 and ending 06:00 belongs to one day for pay and spans two for timestamps. Getting that wrong doesn't crash anything, it silently pays somebody for the wrong number of hours, which is exactly the kind of bug that survives for months.

A missed clock-out is flagged, never guessed

The system will not invent an end time. It marks the shift as needing a human decision, because a plausible guess that reaches payroll is worse than an obvious gap that gets asked about.

Paying someone is one tick, and it is instant

Ticking a box in the dashboard marks that person paid for the period immediately, with no menu, no confirmation step, no script to run. The last mile of a tool is where it gets abandoned.
